Pitfalls

踩過的坑

  • 中文 grounding 永遠接近 0，所有中文回答都被拒答 → 改成 CJK bigram。
  • ingest 一路拿著寫鎖，rebuild 期間聊天寫不進 SQLite → 拆成四段。
  • SQLite 讀回 naive datetime，從新 session resolve approval 直接 crash → 統一用 UTC-aware 型別。
  • 空的 cache 是 falsy，cache or default 默默換掉了 cache → 改成 is not None。
  • timeout 有 5 秒下限，最後一層會超出 time budget。
  • 逐份文件複製向量：300 份時要 3.5 秒；改成跨文件批次後 0.5 秒。
  • eval 計分太寬：檢索被故障弄掉、只好拒答的請求原本也算成功，把 naive 對照組灌高了 → 改成算失敗。

Limits

瓶頸與限制

  • Ollama 是單一本機程序：聊天、背景的記憶抽取、worker 的 embedding 搶同一個模型；第一次呼叫冷啟動約 30 秒。
  • 增量更新仍要把整個語料的向量複製到新 collection，成本是 O(語料) 的複製，不是 O(1)。
  • grounding 是詞彙重疊，不是語意蘊含，換句話說就騙得過。
  • nomic-embed-text 偏英文：Q1 的檢索沒命中最相關的「最佳化實驗室」那份；中文語料建議換 bge-m3。
  • override 的標籤只來自人看過的項目；被拒答的回答沒人看過，無法拿來評分。
