A RAG platform for personal documents: architecture notes

Turn your own documents into a knowledge base you can ask questions. Three ideas carry the design: a complete index version is always serving, a failing model degrades the answer instead of erroring, and answers and memories the system is unsure about go to a human.

Pitfalls

Bugs found along the way

  • Chinese grounding was always near 0, so every Chinese answer was refused → CJK bigrams.
  • Ingest held the write lock throughout, so chat couldn't write to SQLite during a rebuild → split into four phases.
  • SQLite returned naive datetimes, so resolving an approval from a new session crashed → a UTC-aware column type everywhere.
  • An empty cache is falsy, so cache or default silently swapped it out → is not None.
  • A 5 s timeout floor let the last rung overrun the time budget.
  • Copying vectors one document at a time took 3.5 s for 300 documents; batching across documents brought it to 0.5 s.
  • The eval scored too generously: requests refused only because a fault lost the retrieval counted as successes, inflating the no-resilience baseline → they now count as failures.

Limits

Bottlenecks and limits

  • Ollama is a single local process: chat, background memory extraction and the worker's embedding compete for the same model; the first call takes about 30 s to warm up.
  • An incremental update still copies the whole corpus's vectors into the new collection: O(corpus) copying, not O(1).
  • Grounding is lexical overlap, not entailment; a paraphrase can fool it.
  • nomic-embed-text is English-centric: for Q1, retrieval missed the most relevant document (the optimization-lab one). For Chinese corpora, bge-m3 is the better choice.
  • Override labels exist only for items a human looked at; refused answers are never seen, so they can't be scored.
